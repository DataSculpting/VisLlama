# Contributing

Read [Architecture](docs/ARCHITECTURE.md) and [Development](docs/DEVELOPMENT.md)
before changing implementation. Engine authors should also read
[Engine extensions](docs/ENGINES.md).

For bug reports, include the VisLlama version, operating system, engine build,
action, expected result and actual result. Include the relevant error reference
and redacted launch/configuration evidence when available. Do not upload private
`presets/`, complete logs, credentials, prompts or model weights.

Keep changes focused, explain the resulting behavior and report the checks run,
including skips and hardware/browser testing limits. Retain relevant regressions;
do not remove failures to make checks pass. Coordinate dependency changes with
third-party versions, notices and asset hashes.

Preserve the project's [GPLv3 license](LICENSE), [separate additional terms](ADDITIONAL_TERMS.md)
and [third-party notices](THIRD_PARTY_NOTICES.md). See Development for saved-format,
process-ownership and GPU identity contracts that contributions must preserve.
